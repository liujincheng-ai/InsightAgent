# Week 3 面试讲解：RAG 检索、引用与拒答

## 30 秒版本

Week 3 我没有继续堆功能，而是把制度问答拆成“是否检索到正确文档和章节、答案事实
是否完整、每条引用是否真的支持结论、无依据时是否拒答”四个独立问题。我冻结了
40 题和 4 份干扰文档，跑完向量与 BM25 的 54 组参数矩阵，再对多意图问题增加
确定性拆分和跨文档证据扩展。唯一一次 Pro 最终轮的 Document Hit@5 是 100%、
MRR 98.10%、引用精度 100%、拒答 5/5、伪造引用 0；自动事实分数 81.90%，
逐题人工复核为 92.86%，并保留 6 条真实部分遗漏。

## 为什么不能只看“答案像不像对”

RAG 至少有四个不同故障面：

1. 文档没召回；
2. 文档对但章节错；
3. Context 有答案，但模型漏掉关键事实；
4. 答案引用了真实文档，却没有证据支持当前 Claim。

如果只给一个总分，就无法判断应该调 Embedding、Top-K、查询拆分、Prompt 还是评分器。
因此我分开记录 Document Hit、Section Hit、Coverage、MRR、Fact Accuracy、Citation
Precision、拒答和伪造引用。

## 数据集如何防止自欺

- 40 题按单文档、多文档、精确条款和无答案分层；
- dev/test/challenge 分离，只有 dev 可以参与调优；
- 每题预先写 Gold 文档、章节、事实项、不可接受结论和拒答要求；
- 加入已废止旧版、外部建议和临时通知，验证模型不会拿相似文本当现行制度；
- 运行目录与索引不可覆盖，最终 Pro 只跑一次。

开发集评分器审计后，我发现字面匹配会把“上限为 8%”和“上限是 8%”判成不同，
还会把“不得直接取消”中的禁用短语误判为模型真的取消。因此在最终运行前将数据集
升级到 1.0.2，记录修改原因，并保证 test/challenge 回答仍未查看。这比静默改分更可审计。

## 参数实验怎么做

我使用相同问题和语料比较：

- Vector：本地 BGE 中文 Embedding + Chroma；
- BM25：Elasticsearch 8.17.3；
- Chunk Size：256/512/800；
- Overlap：0/50/100；
- Top-K：3/5/8。

共 54 组。原基线 512/50/K5 已达到 Vector 文档/章节 100%、MRR 1.0。BM25 文档
100%，但章节为 95.24%、MRR 0.9762。Top-3 的主要问题不是完全找不到文档，而是
多文档题覆盖不全。

## 多意图问题如何改进

例如“橙色预警客户提出 13% 折扣时，谁负责处置，折扣由谁审批”包含两个子问题。
整句向量检索会被“客户预警”主主题占满，价格审批文档进不了 Top-5。

我的改法不依赖第二次模型调用：

1. 用标点和并列连接词确定性拆分子问题；
2. 保留原查询前三名，避免破坏单问题排序；
3. 在子查询候选中排除旧版和外部材料；
4. 用 RRF 聚合，补入两个不同正式文档的证据。

开发集 Gold Source Coverage@5 从 93.65% 提升到 96.03%，代价是平均检索从
14.4 ms 增至 46.9 ms。这里应明确称为应用层多查询扩展，而不是原生 Hybrid Search。

## 引用精度怎么判

模型必须输出结构化 `claims`。每项包括 Claim、文档名、章节号和证据短句。评分器检查：

- 文档/章节是否真的在当前 Context；
- 证据短句能否在对应 Chunk 原文中定位；
- 无答案题是否明确拒答且没有 Claim；
- 是否引用了 Context 中不存在的来源。

这样“引用了一个看起来权威的文档名”不等于引用正确。

## 如何解释自动 81.90% 与人工 92.86%

我不会只选更高的数字。自动值是固定字符串评分，便于重复运行，但对自然语言同义
表达敏感；人工值逐条检查语义完整性。最终 13 条自动失败中，7 条是等价表达假阴性，
6 条确有事实遗漏。两套分数回答不同问题，必须一起披露。

真实遗漏主要是：

- 第二子问题的质量响应没有召回；
- 只说“分级审批”但没列具体审批人；
- 库存分析漏掉周转、缺货、滞销和在途指标；
- 少数边界条件未写入最终答案。

## 高频追问

### 为什么最终仍选择 Vector，而不是 BM25？

向量检索在相同 512/50/K5 下章节命中和 MRR 更高；BM25 更适合精确关键词，但中文
复合问题容易由高频主题词主导。最终保留 BM25 作为受控对照，不伪装成混合检索。

### 为什么 Top-K 不选 8？

Top-5 已达到 100% 文档和章节命中；Top-8 没有提高向量 Gold Coverage，却增加 Context
噪声和生成成本。多意图扩展比单纯扩大 K 更有效。

### 为什么要保留旧版干扰文档？

没有干扰文档时，召回正确看起来很容易，但无法证明系统能区分“相似内容”和“现行
制度”。干扰文档带 `obsolete/distractor` 元数据，既能测试检索，又能约束答案不能把
旧版当依据。

### 下一步最值得做什么？

先做章节级重排和独立盲测，而不是继续扩大 Prompt。当前失败集中在跨文档第二意图，
说明瓶颈仍在检索覆盖和 Query Planning；同时应引入带理由的语义裁决器，减少字面评分
假阴性，但保留人工抽检。
