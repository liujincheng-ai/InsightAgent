# 项目经历｜上海市大数据中心 / 上海数据集团通用版

## InsightAgent — 企业数据与制度知识协同分析 Agent

**2026.09–至今｜独立项目｜核心开发者**  
**技术栈：** Python、FastAPI、ReAct、PostgreSQL、DeepSeek、RAG、本地中文 Embedding、ChromaDB、SSE、YAML、Docker、Pytest

面向结构化业务数据与制度知识联合分析场景，构建能够理解复杂问题、规划 Tool 调用并输出证据化报告的 Agent，覆盖自然语言问数、异常诊断、风险识别、知识检索和可视化报告；重点解决多步骤任务中的 Tool 误选、SQL 业务口径错误、流程提前结束、失败循环及答案缺少依据等问题。

- **Agent 执行循环与完成契约：** 设计基于 ReAct 的 Thought–Action–Observation 执行链，在 `ToolPack` 中维护“领域分析 → 知识检索 → 报告生成”三阶段状态；越级调用时返回缺失步骤，证据链未完成时限制 `terminate`，避免 Agent 跳过数据查询或直接生成无依据报告。
- **会话记忆与上下文管理：** 以 `conv_id` 隔离会话，组合 Message Memory 与 Plan Memory 保存多轮消息和任务计划，并将执行步骤、计划、输入文件及引用写入结构化历史；按 Token 预算渐进截断旧 Observation、裁剪旧轮次并保留近期上下文，通过 `context.status` SSE 事件暴露占用与压缩层级，同时支持从历史引用直接回答同会话追问，避免重复检索。
- **领域 Tool 与能力封装：** 实现销售诊断、客户流失预警、经销商健康度 3 个独立 Tool，定义参数 Schema、输入校验、失败语义和结构化输出；由 Agent 判断业务意图并选择能力，Tool 通过参数化 SQL 确定性计算同比/环比、加权毛利率、渠道贡献和风险评分。
- **Tool Calling 治理：** 将 Pydantic 枚举、季度格式与数值范围暴露到 Tool Prompt，并在数据库前校验；建立生产兜底与隔离评测双轨。40 题 Flash 三配置选择均值为 93.33%–98.33%，同时如实保留 Pro 文本 ReAct 协议适配失败。
- **Text-to-SQL 业务语义层：** 使用 YAML 统一维护指标公式、单位、同义词、时间半开区间、字段关系和高风险歧义规则，并按问题动态选择相关定义；配合两个只读季度 View 及范围、Join、去重、加权公式预检，降低 SQL 可以执行但分析口径错误的风险。
- **RAG 与证据绑定：** 将六份带稳定章节号的制度文档接入知识检索，对数据事实、制度规则和分析建议分层；最终回答分别绑定 SQL/Tool Observation 与文档章节，高风险数值从查询结果确定性提取或复算，使分析结论能够回查数据和知识来源。
- **故障恢复与执行安全：** 建立语法、表/列、类型、分组、权限、超时等 9 类 SQL 错误反馈；可修复错误仅允许同一步骤纠正一次，相同失败 SQL 直接阻断，DML/DDL 与权限错误立即终止。数据库使用独立只读角色，领域 Tool 使用参数化 SQL，运行凭据通过环境变量注入。
- **Agent 评测与迭代闭环：** 编写真实 SSE 接口评测器，逐题保存 Action、Tool 参数、SQL、Observation、知识引用、延迟和失败类型；V1 独立复验 28/30，语义专项集 27/30；Week 2 Pro 首次 14/40、协议修复后同集复验 38/40；生产三链路烟测 3/3，累计 214 项回归通过。
- **RAG 专项与引用治理：** 构建 40 题与 4 份干扰文档，完成 Vector/BM25 54 组矩阵；最终 Pro 文档命中 100%、MRR 98.10%、引用精度 100%、拒答 5/5、伪造引用 0，自动事实 81.90%、人工逐题裁决 92.86%。

> **结果口径：** 项目使用固定合成数据进行工程验证，不代表生产准确率；Week 2 的 38/40 是同集修复回归，Week 3 自动与人工事实分数同时披露。已实现数据库只读访问、参数校验、Agent 流程门禁与运行轨迹留存，完整 RBAC、Document ACL、多租户和生产审计后台不作为当前成果。
