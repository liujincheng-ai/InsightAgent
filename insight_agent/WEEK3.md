# Week 3 RAG 检索与引用准确性

## 目标

本周只解决一个问题：制度建议是否来自正确文档和章节，以及引用是否真的支持对应结论。

生产知识库保持不变。所有分块、检索器和参数实验使用隔离索引，历史运行结果禁止覆盖。

## 冻结数据集

- 总计 40 条：单文档 15 条、多文档 10 条、精确条款 10 条、无答案 5 条。
- Split：24 dev、12 test、4 challenge。
- 每题标注 Gold 文档、章节、Expected Facts、不可接受结论和拒答要求。
- 只允许根据 dev 失败优化；test 和 challenge 冻结后不参与调参。
- 1.0.0 在首次模型运行前生成；开发集评分器审计后，1.0.2 仅补充同义答案、
  修正否定句判断并移除一个题目未询问的事实。测试与挑战问题未查看，
  1.0.2 在最终运行前冻结并记录 SHA-256。

## 实验语料

- 6 份正式合成制度继续作为有效制度来源。
- 隔离实验语料增加 4 份干扰文档，覆盖已废止旧版、非公司材料和已结束临时通知。
- 干扰文档不进入生产知识库，不得作为现行制度依据。
- 每个分块保留稳定文档名、版本状态、章节号和 chunk ID。

## 检索配置

- Vector：本地中文 Embedding 与 Chroma 索引。
- BM25：本地 Elasticsearch 全文索引。
- Chunk Size：256、512、800。
- Overlap：0、50、100。
- Top-K：3、5、8。
- 先完成无模型的完整检索矩阵，再选择当前基线、最佳 Vector 和最佳 BM25 进入生成评测。
- 多意图问题使用确定性子问题拆分；保留原查询前三名，并用子查询 RRF 选择两个跨文档有效证据，
  不调用模型改写 Query。

现有运行组件虽然提供 Hybrid 枚举，但当前 Chroma 不支持全文检索，Elasticsearch FullText 也不是同索引向量检索。本周不将退化路径包装成 Vector 与 BM25 融合结果。

## 指标

- Document Hit@5。
- 章节命中率。
- Gold Source Coverage@K。
- MRR。
- Answer Fact Accuracy。
- Citation Precision。
- No-answer Accuracy。
- 伪造引用数量。
- 平均检索和生成延迟。

## 验收门槛

- Document Hit@5 不低于 90%。
- MRR 不低于 0.80。
- Answer Fact Accuracy 不低于 90%。
- Citation Precision 不低于 90%。
- 5 条无答案题全部正确拒答。
- 伪造引用为 0。
- 至少完成一组 Chunk、Overlap 和 Top-K 对比。
- Vector 与 BM25 使用相同冻结问题和语料。
- 最佳配置必须同时报告质量变化与延迟代价。
- 原有自动化回归和生产主链路烟测通过。

## 模型纪律

- 开发与候选配置使用 `deepseek-v4-flash`，temperature 0。
- 评分器、Prompt、数据集和最终配置冻结后，使用 `deepseek-v4-pro` 完整运行一次。
- 不因单题或整轮失败补跑，不选择最好一次，不覆盖旧失败轨迹。
- 服务端未返回可审计 Token 时不编造调用费用。

## 引用合同

最终答案中的每个制度性 Claim 必须包含真实文档名、章节和支持该 Claim 的证据短句。无答案题必须明确说明证据不足，不得用行业常识、旧版制度或相似文档补齐结论。

## 对外项目表述

自定义和交付材料统一描述 InsightAgent 的 Agent 编排层、检索层、业务 Tool 层和评测体系，不再使用底层框架品牌作为项目卖点。第三方包名、导入路径、依赖清单和许可证保持真实，不把复用能力描述成从零自研。
