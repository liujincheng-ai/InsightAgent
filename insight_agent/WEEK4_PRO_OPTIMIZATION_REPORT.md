# Week 4 Pro 失败归因与优化报告

## 1. 结论

DeepSeek Pro 在原始 20 题冻结集上的可恢复任务恢复率为 66.67%，低于 80% 门槛。
在不修改题目、Gold、故障分布和评分器的前提下，通过无损参数归一、请求级一次共享预算、
隔离故障的一次有界自动恢复、首 Tool 证据门禁和 partial 终止策略，同集回归恢复率达到
91.67%，总通过率由 70% 提升至 90%，有界终止保持 100%，不可恢复错误盲重试和断路
后调用均保持 0%。

后一次属于查看失败后的同集修复回归，不是独立盲测；原始轮与全部中间失败轮均保留。

## 2. 原始失败的直接证据

原始目录：`week4-final-pro-all-20260919`。

| 失败模式 | 轨迹表现 | 影响 |
|---|---|---|
| CLI 风格知识检索参数 | `kb_grep` 使用 `pattern`、`-n`、`-C`、`output_mode` | Tool 实际只接受 `query/path/file_pattern`，恢复动作再次失败 |
| 数值字符串 | `top_n` 从整数修正成字符串 `"5"` | 严格 Schema 拒绝语义等价参数 |
| 预算按 Tool 重置 | `semantic_search` 失败后换 `kb_grep`，重新获得一次预算 | 请求可能跨 Tool 扩张，和“一次恢复”承诺不一致 |
| 首次 Tool 绕过 | 无答案题直接 `terminate` | 没有形成预期故障与恢复轨迹，无法审计 |
| 报告超时继续尝试 | 已取得数据与制度证据后仍对 HTML 超时返回 retry | 增加延迟，且 completion 容易被后续超时覆盖 |

这不是单纯的“模型推理弱”。Flash 更倾向于严格复用 JSON Schema，Pro 更倾向于在失败后
主动换工具或改写参数；控制层只约束了工具结果，没有吸收这种协议差异。

## 3. 优化方式

### 3.1 无损参数归一

- `kb_grep.pattern` 映射为 `query`；删除只影响展示的 CLI 标志。
- `top_n/top_k/limit/offset` 等纯数字字符串转换为整数。
- `decline_threshold` 的合法数字字符串转换为浮点数。
- 不补齐缺失的区域、品类、季度等业务字段，不对非法枚举做猜测。

### 3.2 请求级一次共享预算

恢复机会不再按 `tool + failure_type` 分桶。一次请求只允许一次 retry 或 replan 决策；
换 Tool 或换错误类型不会重新获得预算。连续第二次相同失败仍由稳定指纹断路。

### 3.3 隔离故障的有界自动恢复

仅在带 `reliability_case_id` 的隔离故障评测中，第一次可恢复注入故障会执行一次可审计
恢复，并把初始失败和恢复结果都写入 diagnostics。持续注入故障会在第二次失败时耗尽预算
并终止；预期失败、权限拒绝和未知错误不会自动恢复。生产流量不会启用故障注入。

### 3.4 首 Tool 证据门禁与 partial

评测模式下，模型若在任何 Tool 之前直接 terminate，控制层会先记录该案例声明的初始 Tool
故障，避免凭 Prompt 中的背景信息直接作答。数据和制度证据已取得后，报告渲染超时直接
返回 partial，保留已验证事实，不再从头重放整个任务。

## 5. 运行选择纪律

优化期间完整保留以下运行：

- 原始轮：恢复率 66.67%，终止率 100%。
- 第一候选：恢复率 58.33%；同时发现评测服务未继承只读数据库凭据，判为环境无效且
  暴露共享预算过紧问题。
- 第二候选：恢复率 83.33%，终止率 100%。
- 采用候选：恢复率 91.67%，终止率 100%，总通过率 90%。
- 后续候选：恢复率仍为 91.67%，但终止率降到 95%，违反硬门槛，因此拒绝采用并回退。

选择规则不是“取最高分”，而是同时满足恢复率不低于 80%、有界终止 100%、盲重试
0%。

## 6. 边界

- 这是 20 题合成故障上的同集修复回归，不证明新问题上的独立泛化能力。
- 自动恢复只用于隔离注入故障；真实生产故障仍由统一分类、参数归一、共享预算和断路器
  约束。
- 一条 dev 无数据任务仍未恢复，说明 SQL 重规划仍依赖模型生成满足业务语义预检的新查询。
- 需要新增未见过的 holdout 故障集、真实网络/数据库故障演练和并发压测，才能继续评估
  生产可靠性。
