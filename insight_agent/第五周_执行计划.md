# InsightAgent 第五周执行计划

> 主题：Context、延迟与调用成本
> 基线提交：`d8ce9c3ed2753bd6519c6e46b08c8289f02dd69e`
> 基线标签：`insight-agent-week4-pro-optimized`
> 执行约束：历史 Markdown 文档保持不变；第五周材料全部新增并使用中文文件名。

## 一、目标

在不牺牲关键事实、时间范围、引用准确性和任务完成率的前提下，验证并优化 InsightAgent
已有多层 Context Management，控制长链 Agent 的输入 Token、延迟和调用成本，并让 SQL
及其他 Tool 的大结果具备“摘要进入上下文、完整结果可追溯”的工程闭环。

## 二、已确认的验收线

- 平均输入 Token 相对 Baseline 下降不少于 15%；
- 估算调用成本下降不少于 10%；
- 20 条任务通过率最多比 Baseline 少 1 题；
- 关键事实保持率不低于 95%；
- 引用准确率下降不超过 5 个百分点；
- 不新增上下文溢出、无引用事实或不可追溯的大结果。

更高结果作为冲刺目标。任何未达标项均保留原始证据，不通过修改评分器或覆盖旧结果
制造成功结论。

## 三、实施步骤

1. 审计 Context Budget、四层压缩、Tool Result Storage、SQL 输出和 SSE 接入链路；
2. 修复配置加载、Layer 3、单轮 Tool Result 总预算和大结果持久化缺口；
3. 增加上下文开关、阈值 Profile 和可审计运行元数据；
4. 新建 20 条长链冻结集，划分 12 dev、6 test、2 challenge；
5. 实现 Token/步骤/结果字符数/延迟/费用/事实与引用评分器；
6. 使用 Flash 运行 Baseline、开发集候选参数和完整集重复稳定性实验；
7. 冻结配置后使用 Pro 完成一次 20 题最终验收；
8. 完成单元测试、InsightAgent 回归、Ruff、运行态 SSE 与安全检查；
9. 根据真实结果生成第五周验收、面试和四类校招项目经历文档；
10. 创建独立 Git Commit 与本地 `insight-agent-week5` 标签，不推送远程。

## 四、20 条长链任务规划

| 类型 | 数量 | 主要验证点 |
|---|---:|---|
| 多步骤 SQL 与跨期比较 | 5 | SQL 大结果、时间范围和核心数值 |
| 领域 Tool 联合分析 | 4 | Tool 顺序、参数、Observation 和事实保持 |
| 跨文档 RAG | 4 | 多意图检索、章节引用和拒答 |
| 大结果与持久化 | 3 | Schema、摘要、Top-N、文件引用和读取边界 |
| 同会话追问 | 2 | 历史状态、证据复用和避免重复检索 |
| 部分失败与边界 | 2 | 压缩后恢复、partial 和有界终止 |

## 五、实验纪律

- 数据集、Gold 和评分合同先冻结，再运行正式实验；
- 每次只改变一个主要变量；
- Flash 用于开发和重复实验，Pro 只在配置冻结后运行一次完整集；
- 价格配置记录来源、查询日期和币种；
- 优先采用 Provider 返回的 Usage；无法取得时使用本地 Token 估算并明确标记；
- 结果目录非空时拒绝覆盖；
- API 调用预算上限 100 元，达到 70 元停止非必要实验并预留 Pro 额度。
