# 项目经历｜央国企 AI 岗

## InsightAgent — 经营数据与制度知识协同分析原型

**2026.09–至今｜独立项目｜核心开发者**  
**技术栈：** Python、FastAPI、PostgreSQL、DeepSeek、RAG、本地中文 Embedding、ChromaDB、YAML、Docker、Pytest

面向企业经营分析与辅助决策场景，将结构化销售数据、指标口径和制度条款接入统一 Agent 流程，支持数据查询、异常诊断、制度取证与报告输出；围绕口径一致、证据可追溯、查询只读和异常可终止建设工程控制。

- **业务数据与验证基线：** 负责区域、产品、客户、销售事实四层数据建模，以固定随机种子生成 60,000 条合成销售明细，并为销售下降、渠道贡献、客户风险和毛利变化建立 Gold Facts；编写六份带稳定章节号的合成制度，确保经营结论能够回查数据库结果与制度依据。
- **会话记忆与上下文治理：** 按 `conv_id` 隔离 Message/Plan Memory，持久化多轮消息、任务计划、执行步骤和引用，支持同会话连续分析与历史引用复用；依据 Token 预算渐进截断旧 Observation、裁剪旧轮次并保留近期上下文，通过 SSE 暴露占用状态和压缩层级，降低长链任务失控与过程不可见风险。
- **指标口径治理：** 针对“销售额/销量混用、毛利率简单平均、贡献率分母不一致、交易区域与客户区域混淆”等问题，建设可版本化 YAML 业务词典，统一公式、单位、时间边界和字段语义；增加两个只读季度聚合 View，分别支撑经营指标汇总和客户跨期比较。
- **可解释领域分析：** 实现销售诊断、客户流失预警、经销商健康度 3 个确定性 Tool，通过参数化 SQL 输出同比/环比、渠道与客户贡献、毛利变化和规则扣分；将“交易异常预警”与“确认客户流失”区分，健康度明确为演示规则版本，避免把相关性或规则评分包装成事实结论。
- **Tool 参数治理：** 为三个领域 Tool 建立区域、品类、季度、阈值和 Top-N 的版本化 Schema，在函数和数据库执行器之前校验；非法参数不会进入数据库。将生产规则兜底与模型自主选择拆成双轨，避免用生产成功率掩盖模型误选和协议失败。
- **数据—制度证据链：** 构建基于 RAG 的企业制度检索，在 `ToolPack` 中维护领域分析、知识检索和报告生成三阶段状态；未获得数据事实时限制制度建议和报告输出，高风险指标从 SQL Observation 计算与呈现，使最终报告能够区分数据事实、制度规则和经营建议。
- **访问控制与异常治理：** 配置 PostgreSQL 独立只读角色、参数化 SQL 和单语句预检；对 SQL 错误分类、脱敏并限制重试，权限和未知错误立即终止。对缺少指标、时间或区域定义的高风险问题先要求澄清，并在当前轮次移除 SQL Tool，避免系统在关键条件缺失时静默采用默认口径。
- **验收与交付：** 建立题目、Gold、原始 SSE 轨迹、SQL、引用和失败原因可关联的验收链路；V1 Pro 独立复验 28/30，Week 1 语义集 27/30。Week 2 首次 Pro 因文本 ReAct 协议兼容问题仅 14/40，修复后一轮同集复验 38/40，Flash boundary 选择 99.17%、参数有效率 100%；生产烟测 3/3、自动化回归 214 项通过。
- **制度检索与引用治理：** 建设 40 题 RAG 冻结集和 4 份旧版/外部干扰文档，完成 Vector/BM25 54 组实验；最终 Pro 的文档命中 100%、MRR 98.10%、引用精度 100%、拒答 5/5、伪造引用 0。自动事实 81.90%，逐题人工裁决 92.86%，并保留 6 条真实遗漏及复核理由。

> **项目边界：** 当前为合成数据上的单机原型；Week 2 首次 14/40 与同集复验 38/40 同时披露，Week 3 自动与人工事实分数同时披露。已落实数据库只读访问、参数前置校验与流程约束；完整 RBAC、Document ACL、多租户和生产审计后台仍属于后续企业化工作。Embedding 在本地运行，生成模型使用远程 API。
