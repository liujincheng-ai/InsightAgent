# Week 4 Agent 失败恢复与稳定性

## 目标

本周只解决 InsightAgent 的执行可靠性：统一识别 Tool 失败、限制恢复次数、阻断重复
失败调用，并让成功、失败和部分完成都有可审计的终态。既有 SQL、Tool Calling 和
RAG 能力不改业务口径。

## 冻结数据集

- 20 条故障用例，12 dev / 6 test / 2 challenge。
- 覆盖 SQL 可修复错误、无数据、RAG 空召回、参数错误、权限拒绝、Tool 异常、
  超时和混合 partial 八类场景。
- 数据集 SHA-256：
  `446c84d32df7bf181a5f477850dfbc6b59ebcbb24d042b90b41cfb2d5d8851cc`。
- 故障只在显式评测开关和冻结 case ID 下按请求注入，不污染生产数据、数据库或
  共享 Tool。

## 可靠性合同

1. 结果先分类为 `success`、可修复失败或不可修复失败，不能把 HTTP/函数正常返回的
   错误对象当作成功。
2. SQL、参数、Tool 异常和超时最多修正重试一次；无数据、RAG 空召回和工作流阻断
   最多换策略一次。
3. 权限拒绝和未知错误立即终止。
4. 同一 Tool、规范化参数和错误类型形成稳定指纹；连续两次相同失败打开断路器。
5. 已有成功 Observation 时，后续失败返回 `partial`，明确已完成、未完成、原因和
   下一步；不得补写没有证据的制度或数值。
6. 外层请求超时也必须写出可靠性轨迹并保留已验证结果。

## 步数与超时

- 生产默认：数据库 5 步、知识 6 步、集成 5 步。
- 冻结故障基准按 case 使用数据库 5、知识 6、集成 8 的上限。
- Flash After 三轮中，数据库/知识/集成观测 P95 分别为 3/5/7；集成生产链路在
  第 5 步证据齐备后使用确定性 HTML fallback，避免无价值的额外模型轮次。
- 请求级上限为 120 秒；评测客户端给 150 秒以接收服务端终止事件。

## 验收门槛

- 20 条数据集可复现且原始 SSE 不覆盖。
- After 有界终止 100%。
- 不可恢复错误盲重试率 0%。
- 相同失败指纹连续两次时，断路器触发率 100%，触发后调用率 0%。
- 可恢复任务恢复率不低于 80%。
- `success/failed/partial` 与冻结期望一致。
- 主 Demo 严格 rubric 三次全部通过。
- Week 1–3 回归不退化。

## 模型纪律

- `deepseek-v4-flash` 对 Before/After 各完整运行三次，temperature 0。
- 发现评测桥阻塞缺陷后，保留 candidate1 六轮并整套重跑 candidate2；没有替换单题。
- 最终配置冻结后，`deepseek-v4-pro` 只完整运行一次，不因结果失败补跑。
- 服务端没有可审计 Token 时，不编造成本。

## 结果边界

Flash candidate2 达到工程门槛；Pro 原始运行恢复率 66.67%，未达到 80%。用户后续
明确要求优化后，通过无损参数归一、请求级共享预算、有界自动恢复和首次 Tool 证据门禁，
同集回归达到 91.67%，总通过率 90%，有界终止 100%。原始与中间失败轮全部保留，
后一次不能表述为独立盲测。
