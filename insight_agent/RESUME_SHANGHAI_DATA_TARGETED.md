# InsightAgent 定向项目简历｜上海市大数据中心 / 上海数据集团

> 两个版本都以 Agent 项目为主体，只在项目说明和最后一条中体现岗位侧重点。正式投递时选择对应版本。

## 版本 A｜上海市大数据中心

### InsightAgent — 企业经营数据与制度知识协同分析 Agent

**2026.09–至今｜独立项目｜核心开发者**  
**技术栈：** Python、FastAPI、ReAct、PostgreSQL、DeepSeek、RAG、本地中文 Embedding、ChromaDB、SSE、YAML、Docker、Pytest

面向“销售为何下降、哪些客户存在风险、制度允许采取什么措施”等复杂经营问题，构建能够自主选择 SQL、领域 Tool 和知识检索的分析 Agent；重点解决多步骤任务中的 Tool 误选、SQL 语义错误、流程提前结束、失败循环和答案缺少证据等问题，并形成可追踪的执行与评测链路。

- **Agent 执行循环与完成契约：** 设计基于 ReAct 的 Thought–Action–Observation 执行链，在 `ToolPack` 中维护“领域分析 → 制度检索 → 报告生成”三阶段状态；越级调用时返回缺失步骤，证据链未完成时限制 `terminate`，避免 Agent 跳过数据查询或直接生成无依据报告。
- **会话记忆与上下文治理：** 以 `conv_id` 隔离 Message/Plan Memory，持久化消息、任务计划、执行步骤与引用；依据 Token 预算渐进压缩旧 Observation 和历史轮次，通过 SSE 输出上下文状态，并支持同会话引用追问直接复用历史证据。
- **领域 Tool 系统：** 将销售诊断、客户流失预警、经销商健康度拆分为 3 个独立 Tool，设计参数 Schema、输入校验和结构化输出；由 Agent 判断意图并选择能力，Tool 通过参数化 SQL 确定性计算同比/环比、加权毛利率、渠道贡献和风险评分，降低模型直接计算关键指标产生的漂移。
- **Tool Calling 评测与参数治理：** 扩展 `FunctionTool` 的 Schema 约束展示和执行前校验，非法参数在数据库前被阻断；建设 40 题三配置重复实验，从 Pro 首次 14/40 定位文本 ReAct 协议缺口，兼容修复后同集复验 38/40，Flash `boundary` 选择 99.17%、参数有效率 100%。
- **Text-to-SQL 语义增强：** 建设 YAML 业务词典，维护指标公式、单位、时间半开区间、字段关系与歧义规则，并根据问题动态选择相关语义；配合两个只读季度 View 及范围、Join、去重、加权公式预检，处理“SQL 可以执行但业务口径错误”的问题。
- **RAG 与证据绑定：** 将六份带章节号的制度文档接入知识检索，对数据事实、制度规则和经营建议分层；高风险数值从 SQL/Tool Observation 确定性提取或复算，制度结论保留文档章节，使最终答案能够回查数据来源和知识依据。
- **错误恢复与执行安全：** 建立语法、表/列、类型、分组、权限、超时等 9 类 SQL 错误反馈；可修复错误仅允许同一步骤纠正一次，相同失败 SQL 阻断，DML/DDL 与权限错误立即终止。数据库使用独立只读角色，领域 Tool 使用参数化 SQL，避免 Prompt 成为唯一安全防线。
- **Agent 评测与运行观测：** 编写真实 SSE 接口评测器，逐题保存 Action、Tool 参数、SQL、Observation、引用、延迟和失败类型；V1 独立复验 28/30、语义专项集 27/30，Week 2 Pro 首次 14/40、协议修复后同集 38/40；生产 RAG、业务 Tool、集成 HTML 烟测 3/3，累计 214 项回归通过。
- **RAG 检索与引用治理：** 构建 40 题和 4 份干扰文档，完成 Vector/BM25 54 组矩阵；唯一 Pro 最终轮文档命中 100%、MRR 98.10%、引用精度 100%、拒答 5/5、伪造引用 0，自动/人工事实为 81.90%/92.86%。

**岗位贴合点：** 项目核心仍是 Agent 开发；面向市大数据中心时，重点讲高准确场景中的语义口径、跨数据与知识资源协同、只读访问、运行观测和结果追溯。

## 版本 B｜上海数据集团

### InsightAgent — 企业经营数据与制度知识协同分析 Agent

**2026.09–至今｜独立项目｜核心开发者**  
**技术栈：** Python、FastAPI、ReAct、PostgreSQL、DeepSeek、RAG、ChromaDB、SSE、YAML、Docker、Pytest

面向企业经营分析场景，构建能够理解业务问题、规划工具调用并整合数据与知识证据的 Agent，覆盖自然语言问数、销售下滑诊断、客户风险识别、经销商健康评估和 HTML 报告；通过语义层、领域 Tool、执行门禁与评测体系提升数据应用的稳定性和可验证性。

- **Agent 执行循环与任务编排：** 基于 ReAct 构建多步骤分析链，通过 `ToolPack` 管理领域分析、知识检索和报告生成状态；对越级 Tool 调用返回结构化反馈，在必要步骤缺失时阻断提前结束，使复杂任务从自由生成转为有完成条件的 Agent 工作流。
- **会话记忆与上下文治理：** 以 `conv_id` 管理 Message/Plan Memory 和结构化历史，保存多轮消息、任务计划、执行轨迹与引用；依据 Token 预算渐进压缩旧 Observation 和历史轮次，并将上下文状态通过 SSE 暴露给前端，支撑长链任务持续运行与问题追溯。
- **领域 Tool 与能力封装：** 实现销售诊断、客户流失预警、经销商健康度 3 个业务 Tool，定义清晰的输入、输出与失败语义；将同比/环比、下降贡献、毛利变化和规则评分封装为可复用能力，支持 Agent 按场景选择、组合和独立验证。
- **Tool 契约与双轨实验：** 为领域 Tool 增加枚举、季度格式、数值范围和未知字段拒绝，并在数据库前执行 Schema 校验；隔离评测模型自主选择，生产保留规则兜底。Pro 首次 14/40 暴露协议缺口，修复后同集复验 38/40。
- **Text-to-SQL 业务语义层：** 使用 YAML 管理指标、单位、同义词、时间范围与字段语义，按问题动态注入相关定义；结合只读季度 View 和 SQL 预检控制 Join、去重与加权公式，将原始销售明细转化为 Agent 可稳定消费的业务指标能力。
- **真实问题定位与修复：** 在渠道下降分析中，对比 SQL、Observation 与 Gold Facts，定位模型将“所有下降渠道之和”误作贡献率分母，产生 73.99% 与正确口径 74.89% 的偏差；重构范围净下降定义并增加确定性复算，后续专项运行中该回归案例通过。
- **RAG 证据链与故障收敛：** 将结构化数据结果与制度知识检索接入同一任务，最终回答分别绑定 SQL/Tool Observation 和制度章节；对 SQL 错误分类、脱敏并限制重试，相同失败调用直接阻断，避免循环消耗和无依据补全。
- **Agent Benchmark 与迭代闭环：** 构建综合、Text-to-SQL 和 Tool Calling 冻结集，逐题记录工具、参数、SQL、引用和失败分类；V1 Pro 独立复验 28/30、语义专项集 27/30，Week 2 Pro 首次 14/40、协议修复后同集 38/40；生产烟测 3/3、累计 214 项回归通过。
- **RAG Benchmark：** 建设 40 题、4 份干扰文档与 54 组检索实验；最终 Pro 文档命中 100%、MRR 98.10%、引用精度 100%、拒答 5/5、伪造引用 0，自动事实 81.90%、人工逐题裁决 92.86%，保留 6 条真实遗漏。

**岗位贴合点：** 项目核心仍是 Agent 开发；面向上海数据集团时，重点讲如何把数据、指标和分析方法封装为可复用 Tool 与语义能力，以及如何通过证据、轨迹和失败评测支撑数据应用产品持续迭代。

## 使用建议

两版都保留 Agent 执行循环、Tool Calling、Text-to-SQL、RAG、失败恢复和 Benchmark 六条主线。投递市大数据中心时使用版本 A；投递上海数据集团时使用版本 B。不要把两个版本同时放入一份简历。

项目使用固定合成数据进行工程验证，不代表生产准确率；Week 2 是同集协议修复回归，Week 3 自动与人工事实分数同时披露。数据库只读角色、参数校验、流程门禁与轨迹留存已经实现，完整 RBAC、Document ACL、多租户和生产审计后台不作为现有成果。
