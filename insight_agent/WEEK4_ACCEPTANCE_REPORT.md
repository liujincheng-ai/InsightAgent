## Pro 失败归因与优化后复验

原始轨迹显示，Pro 比 Flash 更常出现四类行为：

1. `semantic_search` 失败后改用 `kb_grep`，但输出 `pattern/-n/output_mode` 等 CLI 风格参数；
2. 将整数参数修正为字符串，例如 `top_n="5"`，被严格 Schema 拒绝；
3. 从一个 Tool 换到另一个 Tool 后，原实现按 `tool + failure_type` 重新获得恢复预算；
4. 无答案题可能直接 terminate，跳过预期的首次检索故障，轨迹不可审计。

修复采用无损参数别名与标量归一、请求级一次共享预算、隔离注入故障的一次有界自动
恢复、首次 Tool 证据门禁，以及报告超时后的 partial 失败关闭。不会猜测缺失业务参数，
持续故障和不可恢复错误仍终止。

## 主 Demo 与回归

最初 3 次主 Demo 因多余模型轮次超时为 0/3；将生产集成链路上限收紧到 5 并复用
证据绑定 fallback 后为 2/3，唯一失败是模型跳过计划事件；将固有三阶段计划确定性写入
SSE 和历史后，最终三次严格九项均为 3/3，平均 74.29 秒。

最终 `tests/insight_agent` 为 199 passed。Week 1–3 数据、评分器和行为测试均在该套
回归中，没有发现退化。

## 风险与边界

- Pro 66.67% 原始失败和所有中间回归必须保留；91.67% 是查看失败后的同集修复回归。
- 故障为隔离注入，验证的是策略和执行边界，不等同于真实网络、数据库和权限系统的
  全部分布。
- 20 题与单机环境不足以证明生产 SLO、高可用、多租户和审计合规。
- 生产默认集成 5 步依赖确定性 fallback；新增报告类型需要补充对应证据合同和回归。
