## 3. 第五周实现

### 3.1 上下文预算闭环

- 修复 `ContextManager` 未保存 `model_name` 导致 Layer 3 压缩运行时失败的问题。
- 将配置、模型元数据和请求级 `context_profile` 接入真实初始化链路。
- 提供 `baseline`、`balanced`、`aggressive` 三档受控配置；不允许请求任意注入预算值。
- 保留四层机制：旧 Observation 微压缩、旧轮次裁剪、LLM 摘要和溢出后应急裁剪。
- 通过 SSE 输出 `used/budget/ratio/state/compact_layer`，便于评测与前端观测。

本轮正式任务经过工具面收敛和大结果治理后未达到压缩触发阈值，因此运行轨迹中
`context_layer_counts` 为空。这不是“压缩失败”，而是上下文在触发前已被控制；各压缩层
由自动化测试覆盖。不能把 50.01% 的全部降幅归因于某一压缩算法，主要贡献来自聚焦
Prompt、缩小综合模式 Tool Surface、确定性结果呈现和大结果摘要化。

### 3.2 大结果持久化

- SQL 不再先截断后假称“完整结果仍可用”。当结果超过 50 行或 20,000 字符时，先将
  完整 Markdown 结果落盘，再向模型返回字段、总行数、Top-10 和文件路径。
- 对“完整结果必须可追溯”的请求，语义预检拒绝 `LIMIT` 和窗口排名 Top-N 过滤，防止
  模型只查询展示行却声称已保存全量数据。
- 工具结果支持单结果阈值和逐轮累计预算；超过预算的结果自动落盘并保留预览。
- `read_persisted` 改用真实公共路径校验，修复字符串前缀可能越过存储目录的问题。

### 3.3 综合 Agent 上下文收敛

- 综合经营模式从通用大工具集收敛为领域 Tool、知识检索、HTML、只读 SQL、结果读取和
  `terminate`，不再向模型宣传不存在的并行委派、Shell 或代码工具。
- 工作流门控由“只完成一个主领域 Tool”升级为“完成题目明确要求的领域 Tool 集合”。
- 最终报告合并全部已验证领域 Observation，并确定性保留毛利变化、折扣变化、引用文档
  与章节，减少长链末端丢事实。

## 4. 运行结果

### 4.1 Flash 正式验收

正式聚合结果目录：`evaluation/results/week5-accepted-aggregate-20260919`。

- 15/20 通过，较基线增加 3 题。
- 关键事实 95%，引用 95.45%。
- 平均估算输入 Token 下降 50.01%，平均估算成本下降 47.90%。
- 平均延迟从 12.376 秒降至 8.204 秒，P95 从 33.750 秒降至 15.626 秒。
- 2/20 用例观察到完整 SQL 结果持久化；其余用例结果未达到落盘条件。
- 0 次上下文溢出，0 次传输错误。

项目保留该失败，不补跑、不挑选更好结果。

## 5. 补跑披露

- 基线 `w5-dev-integrated-02`：主运行发生连接重置；固定补跑后网络正常但任务仍失败，
  因此基线通过数没有提高。
- 优化 `w5-dev-rag-02`：主运行直接输出占位句，未形成任何检索证据；固定一次补跑通过。
- 优化 `w5-dev-integrated-03`：增加已存在于 Tool Observation 的毛利变化确定性呈现，
  单测通过后补跑通过。
- 优化 `w5-test-sql-03`：支持两类折扣列别名和两类季度标签，确定性计算两个百分点差值，
  单测通过后补跑通过。

补跑后的聚合结论是“修复回归”，不是新的独立盲测。原始主运行仍单独报告为 12/20、
关键事实 85%、引用 86.36%。

## 6. 自动化与复现

核心命令：

```powershell
.\.venv\Scripts\python.exe -m pytest tests/insight_agent packages/dbgpt-core/src/dbgpt/agent/core/context/tests -q
.\.venv\Scripts\python.exe -m insight_agent.evaluation.context_profiler --model deepseek-v4-flash --profile balanced --split all --output-dir <新目录>
.\.venv\Scripts\python.exe -m insight_agent.evaluation.context_compare --baseline-dir <基线目录> --optimized-dir <优化目录> --output-dir <新目录>
```

评测器保存逐题原始 SSE、答案、Tool、上下文状态、估算 Token、延迟、成本、事实与引用
评分；结果目录禁止覆盖。

## 7. 项目边界

- 数据、制度和问题均为固定合成资产，不能外推为生产准确率。
- 当前没有供应商真实 Token Usage 和账单回传，费用只能称“估算”。
- 单机原型尚未实现完整 RBAC、Document ACL、多租户、审计后台和并发压测。
- 受模型路径波动影响，正式结论同时保留主运行、补跑和唯一 Pro 失败结果。
