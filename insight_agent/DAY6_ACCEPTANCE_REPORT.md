Day 6 围绕 SQL 安全恢复、精确事实呈现和综合 Agent 的证据闭环完成收口：

1. 建立 SQL 错误分类、脱敏 Observation、一次纠正预算、重复 SQL 阻断和不可重试错误立即停止；

6. 强制综合任务依次取得领域 Tool、真实制度证据和 HTML 输出，阻断冗余 SQL 与“未执行但声称完成”；
7. 经销商制度证据不足时执行定向语义检索，并在恢复后强制重新渲染证据绑定报告；
8. 将综合任务最大轮数从 12 收紧到 8，为确定性恢复留出时间；
9. 新增并扩展 SQL presenter、工作流门禁和知识检索恢复测试，补充 pytest asyncio fixture 配置。

## 4. 后续发现的四个事实表达问题

首轮达到门槛的候选仍有四个 Text-to-SQL 失败：`v1-dev-sql-04`、`v1-dev-sql-05`、`v1-test-sql-07`、`v1-test-sql-08`。它们不是 SQL 执行失败，而是查询结果别名和形状变化后，presenter 未稳定识别毛利率、季度行、渠道贡献或客户下降金额。

解决方式包括：

- 兼容 `q1_gp/q2_gp`、`q1_margin/q2_margin`、紧凑季度别名及 `qtr + gross_margin` 行式结果；
- 同时输出品类环比变化率和绝对降幅，避免负号语义丢失；
- 支持从 Q1/Q2 销售额推导渠道变化额，并兼容多种变化额、贡献率别名；
- 单行渠道结果缺少贡献率时不再自行计算，转入受限纠正；
- 兼容客户下降金额常见别名。

修复后先进行四题定向回归，结果 4/4；随后重新执行完整固定 30 题，结果 30/30。

## 8. 遇到的问题与解决方式

| 问题 | 原因 | 解决 |
|---|---|---|
| SQL 合法却被拒绝 | JOIN 关键字被正则识别为别名 | 调整别名解析并增加派生表测试 |
| SQL 正确、答案错误 | LLM 重抄数值或重新计算 | 结构化 Observation + 确定性 presenter |
| 结果列名/形状变化导致漏识别 | presenter 覆盖不足 | 扩展季度、毛利、渠道、客户等语义别名与计算路径 |
| 渠道贡献被误算成 100% | `LIMIT 1` 且无贡献率列 | 预检贡献列，强制唯一一次纠正 |
| Tool 间接调用或重复 SQL | 模型动作漂移 | 原生 ToolPack 门禁和窄形状恢复 |
| 综合任务假完成 | 完成判断依赖自然语言 | 完成绑定真实 SSE Tool 事件 |
| 制度选错或只输出查询映射 | 广义召回或缺失 ReAct Action | 执行真实定向 `semantic_search` 并绑定引用 |
| HTML 偶发未完成 | Agent 轮数耗尽 | 减少冗余动作，将轮数预算留给确定性恢复 |
| 稳定性脚本解析异常 | 引用来源可能是结构化对象 | JSON 序列化兼容结构化引用 |
| pytest asyncio 警告 | fixture loop scope 未显式配置 | 设置 function scope |
