# 项目经历｜私企 Agent 开发岗

## InsightAgent — 企业经营分析智能体

**2026.09–至今｜独立项目｜核心开发者**  
**技术栈：** Python、FastAPI、ReAct、PostgreSQL、DeepSeek、RAG、ChromaDB、SSE、YAML、Docker、Pytest

面向汽车配件销售诊断场景，构建能够联合分析经营数据与企业制度的 Agent，覆盖自然语言问数、销售下滑归因、客户风险识别、经销商健康评估和 HTML 报告；重点解决自由 Tool Calling 中的流程越级、SQL 业务口径错误、失败循环与答案缺少证据等问题。

- **Agent 执行编排与完成契约：** 基于 `ToolPack` 设计三阶段运行状态，将综合任务约束为“领域分析 → 制度检索 → 报告生成”；对越级 Tool 调用返回缺失步骤，并在证据链未完成时阻断 `terminate`，解决模型仅凭 Prompt 容易跳过数据查询、提前生成报告的问题。
- **会话记忆与长上下文治理：** 以 `conv_id` 管理 Message/Plan Memory，持久化多轮消息、任务计划、执行步骤与引用；基于 Token 阈值渐进截断旧 Observation、裁剪旧轮次并保留近期上下文，通过 SSE 输出上下文状态，同时复用历史引用处理同会话追问，减少重复检索和长链任务的上下文膨胀。
- **领域 Tool 与确定性指标引擎：** 独立实现销售诊断、客户流失预警、经销商健康度 3 个参数化 SQL Tool，将同比/环比、加权毛利率、渠道下降贡献和客户风险等稳定逻辑从 LLM 推理下沉到代码；由 Agent 负责意图理解与工具选择，工具负责可复核计算，避免“万能 Tool”参数复杂和纯生成计算漂移。
- **Tool Calling 契约与隔离评测：** 扩展 `FunctionTool`，将 Pydantic 枚举、正则、数值范围和未知字段约束写入 Tool Prompt，并在数据库访问前返回结构化 `invalid_arguments`；建设 40 题、三配置、三重复的隔离评测，Flash 选择准确率均值为 93.33%–98.33%，同时定位 Pro 大量输出不符合文本 ReAct 协议的兼容问题。
- **Text-to-SQL 业务语义层：** 将指标公式、单位、时间半开区间、字段含义和歧义规则沉淀为 YAML 词典，按当前问题选择相关语义注入上下文；建设季度经营与客户销售两个只读聚合 View，并增加范围保留、Join、去重和加权公式预检，降低 SQL 可执行但经营口径错误的风险。
- **具体语义故障修复：** 在渠道下降分析中，通过实际 SQL、Observation 与 Gold Facts 对比，定位模型将“所有下降渠道之和”误作分母，得到 73.99%，而整体净下降口径应为 74.89%；重构贡献率定义并从完整渠道结果确定性复算，同时补齐 Q1/Q2 毛利率事实，后续专项运行中两个回归案例均通过。
- **失败恢复与安全边界：** 建立语法、表/列、类型、分组、权限、超时等 9 类 SQL 错误反馈；可修复错误仅允许同一步骤纠正一次，相同失败 SQL 直接阻断，DML/DDL 和权限错误失败关闭。领域 Tool 使用参数化 SQL，通用入口做单语句只读校验，PostgreSQL 独立只读账号承担最终写保护。
- **可观测评测与回归：** 编写真实 SSE 接口评测器，逐题保存 Tool、参数、SQL、Observation、答案和失败类别；V1 首次独立复验 28/30，Week 1 语义专项集 27/30。Week 2 首次 Pro 14/40 暴露协议解析缺口，兼容修复后同集复验 38/40；生产 RAG、业务 Tool、集成 HTML 烟测 3/3，累计 214 项自动化回归通过。
- **RAG 检索与引用评测：** 构建 40 题与 4 份干扰文档，完成 Vector/BM25 共 54 组参数矩阵；以确定性多意图拆分和跨文档证据扩展将开发集 Coverage@5 从 93.65% 提升到 96.03%。唯一 Pro 最终轮 Document Hit@5 100%、MRR 98.10%、引用精度 100%、拒答 5/5、伪造引用 0；自动事实 81.90%，逐题人工裁决 92.86%，保留 6 条真实部分遗漏。

> **结果口径：** 以上均为固定合成数据集上的工程验证。不同题集和模型结果不横向混算；Week 2 的 38/40 是检查首次 14/40 后的同集修复回归。Week 3 自动与人工事实分数必须同时披露，不扩大为生产准确率。
