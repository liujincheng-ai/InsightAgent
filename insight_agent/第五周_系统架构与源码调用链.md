# InsightAgent 第五周系统架构与源码调用链

## 一、运行链路

```text
用户问题
  → Agent API：识别上下文档位与任务类型
  → 领域策略：收敛工具面、校验 SQL/工具完成合同
  → BaseAgent：开始新一轮并重置工具结果滚动预算
  → ToolAction：执行 SQL、领域工具或 RAG
  → ToolResultStorage：判断内联、截断或完整落盘
  → ContextManager：监测 Token 比例并执行分层压缩
  → SSE：输出上下文状态、步骤、工具 Observation 与最终答案
  → 第五周评测器：评分事实、引用、任务、延迟、Token 与估算成本
```

## 三、Context 档位

第五周保留 `baseline`、`balanced`、`aggressive` 三档。正式优化使用 `balanced`：最大上下文
60,000 Token、预留 4,096 Token、最近保留 5 轮、工具结果默认阈值 12,000 字符、单轮累计
预算 24,000 字符、预览 1,200 字符；SQL 与语义查询可使用更严格的 8,000 字符覆盖阈值。

档位通过请求扩展字段选择，未显式选择时使用受控默认值。`max_context_tokens=0` 保留为自动
识别，不会被配置加载错误地替换成硬编码上限。

## 四、大结果追溯链路

SQL 返回超过 50 行或 20,000 字符时，系统先将完整结果写入工具结果目录，再在模型上下文中
放入 Top 10 摘要和 `<persisted-output>` 引用。普通工具结果则按工具阈值与单轮累计预算决定
是否落盘。读取时使用规范化路径和 `commonpath` 校验，阻止相似目录前缀绕过边界。

“回答只显示前 10 名但完整结果必须可追溯”的请求会触发 SQL 静态规则：禁止在查询本身使用
`LIMIT` 或以窗口排名筛掉其余记录，避免模型只拿到不可恢复的局部数据。

## 五、评测调用链

`long_context_test.json` 固化 20 条任务及 Gold；`context_profiler.py` 解析 SSE 并计算事实、引用、
上下文层级、延迟和工具轨迹；`cost_calculator.py` 用统一价目与汇率估算费用；
`context_compare.py` 合并主运行和显式补跑，输出原始聚合记录、JSON 对比与中文报告。

结果目录使用“已存在即拒绝创建”的方式防止覆盖。补跑替换映射进入 provenance，确保主结果、
替换用例和最终判断都可以反查。

## 六、安全与可观测性

- SQL 继续沿用只读校验、表字段白名单和时间范围约束；
- 持久化路径限制在运行目录，拒绝兄弟目录前缀和越界读取；
- SSE 保留步骤、工具、上下文状态和最终答案，便于离线复算；
- API 密钥只存在于服务进程环境中，不写入代码、配置、日志或文档；
- 临时评测服务已关闭，原有 5670 服务保持运行。
