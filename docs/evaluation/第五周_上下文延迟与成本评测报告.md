# 第五周上下文、延迟与成本评测报告

## 一、评测目标

在保持任务质量的前提下，验证 `balanced` 上下文档位能否降低长链 Agent 的输入 Token、延迟
和调用成本，并检查 SQL 等大结果是否能够“摘要进入上下文、完整内容可追溯”。

验收线为：平均输入 Token 下降不少于 15%，估算成本下降不少于 10%，任务通过数最多下降
1 题，关键事实保持率不低于 95%，引用准确率下降不超过 5 个百分点，并且无新增上下文溢出
或传输错误。

## 二、数据与方法

- 冻结集共 20 题：12 条开发集、6 条测试集、2 条挑战集；
- SHA-256：`18ef89524a93dce6ae4c9eeebe3070bb25f3b0e140743d60525dea0452a3024c`；
- 覆盖多步 SQL、领域工具组合、跨文档 RAG、大结果追溯、会话追问和部分失败；
- Flash 用于基线、开发和重复验证；配置冻结后只运行一次 Pro 完整集；
- Token 和费用为本地估算，不是供应商账单；两组使用相同估算口径；
- 对明确的传输异常或确定性呈现缺口使用补跑替换，替换映射写入聚合 provenance，原结果保留。

## 四、唯一 Pro 终验

冻结配置后的唯一一次 Pro 完整集结果为 9/20，关键事实保持率 78.33%，引用准确率 68.18%，
平均估算输入 Token 21,178.35，平均延迟 15.040 秒，估算总成本 4.159386 元。该结果不满足
质量验收线，没有补跑，也没有替换 Flash 的正式验收结论。

这个反例说明更高价格或更强通用能力不等于更适配当前工具协议。后续应针对 Pro 的工具调用、
完成条件和引用格式建立独立协议适配层，再使用新的盲测集验证，而不是重复运行挑选结果。

## 五、结果解释与限制

1. 50.01% 输入降幅由聚焦提示词、工具面收敛、预算配置和大结果控制共同贡献；本轮只在
   10% 用例触发持久化，不能把全部收益归因于压缩或落盘。
2. 正式聚合属于透明的修复回归，不能替代一套从未参与调参的独立盲测。
3. 本地 Token 估算适合相对比较，不应被描述为供应商精确用量或账单节省。
4. 延迟受网络和模型服务波动影响；当前结果说明本轮样本内改善，不代表并发生产负载。

## 六、结论

第五周在既定的面试竞争力标准下验收通过：质量没有退化，任务通过数反而增加 3 题；平均
估算输入 Token、费用、平均延迟和 P95 延迟均明显下降；大结果具备完整追溯路径。与此同时，
Pro 失败和补跑边界均被原样记录，使结论可以在面试或复核时被诚实解释。
